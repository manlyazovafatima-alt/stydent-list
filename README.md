# Group Space — список учащихся

Небольшое адаптивное веб-приложение на чистых **HTML, CSS и JavaScript**. Для общей базы данных используется Supabase; статическую часть можно опубликовать через GitHub Pages.

## Возможности

- поиск по любой части ФИО, телефону, адресу и дополнительным сведениям;
- показ/скрытие полного списка группы;
- добавление и редактирование карточек;
- массовый импорт имён построчно или в формате `номер | ФИО`;
- сохранение данных в общей базе Supabase;
- обновление открытых устройств через Supabase Realtime;
- вход по email и паролю, ограничение доступа по email и Row Level Security (RLS);
- демонстрационный режим с тестовыми записями — без настоящих личных данных.

## 1. Посмотри интерфейс

Открой `config.js` и оставь `demoMode: true`. Открой `index.html` в браузере. Демонстрационные изменения сохраняются только в текущем браузере и не синхронизируются с другими устройствами.

## 2. Создай онлайн-базу данных

1. Создай проект в [Supabase](https://supabase.com/dashboard).
2. В разделе **Authentication → Users** создай одного пользователя с email и паролем. Не включай публичную регистрацию для этого учебного каталога.
3. Открой **SQL Editor**, открой файл `supabase-setup.sql`, замени `YOUR_LOGIN_EMAIL@example.com` на email созданного пользователя и выполни весь SQL.
4. В настройках проекта найди **Project URL** и **Publishable key** (или старый `anon` public key, если проект показывает именно его).
5. В `config.js` укажи эти значения и тот же email:

```js
window.APP_CONFIG = {
  demoMode: false,
  supabaseUrl: "https://ТВОЙ_PROJECT_ID.supabase.co",
  supabasePublishableKey: "ТВОЙ_PUBLISHABLE_KEY",
  adminEmail: "ТВОЙ_EMAIL@example.com"
};
```

6. Сохрани файл и открой сайт снова. Войди с созданным email и паролем.

**Не используй `service_role` или secret key во фронтенд-коде.** Публичный ключ допустим в браузере только вместе с корректными RLS-политиками. SQL в этом проекте разрешает чтение, добавление и изменение только пользователю с указанным email; анонимный доступ и удаление записей через приложение не разрешены.

## 3. Импортируй список

1. Войди в приложение.
2. Нажми **Список группы → Импортировать список**.
3. Вставь строки, по одной на запись. Можно вставлять без номеров; приложение назначит порядковые номера автоматически. Для сохранения исходных номеров используй формат `5 | ФИО`. Строка `4 |` оставит пропуск под номером 4 и не добавит пустую запись.
4. Нажми **Импортировать записи**.

Личные данные вводятся в приложение после входа, а не хранятся в исходном коде репозитория.

## 4. Опубликуй сайт на GitHub Pages

1. Создай новый репозиторий на GitHub. Не загружай в него файлы с реальными адресами, телефонами или полным списком учащихся.
2. Загрузи `index.html`, `style.css`, `app.js`, `config.js` и `supabase-setup.sql` (этот README тоже можно загрузить).
3. Открой **Settings → Pages**.
4. Выбери публикацию из ветки `main` и папки `/ (root)`, затем сохрани настройки.
5. Открой URL, который покажет GitHub Pages, и войди с той же учётной записью. На другом устройстве открой эту же ссылку и войди снова.

`config.js` содержит адрес проекта и публичный ключ, но не должен содержать пароль или секретный ключ. Доступ к данным всё равно должен проверяться базой данных через RLS.

## 5. Проверка перед сдачей

- [ ] Поиск по одной букве и по полному ФИО работает.
- [ ] Кнопка «Список группы» показывает список.
- [ ] Добавление и редактирование сохраняются после перезагрузки.
- [ ] На втором устройстве можно войти и увидеть те же записи.
- [ ] Неавторизованный посетитель не получает данные группы.
- [ ] В репозитории нет списка личных данных учащихся.

## Как объяснить проект на защите

«Я создала адаптивное веб-приложение на HTML, CSS и JavaScript. HTML отвечает за структуру, CSS — за оформление и адаптацию под экран, а JavaScript — за поиск, отображение, добавление и редактирование записей. Supabase хранит данные в общей базе, а авторизация и Row Level Security ограничивают доступ. GitHub Pages публикует статические файлы сайта, поэтому сайт можно открыть по одной ссылке на разных устройствах».
